## 記事タイプ: note連動・技術実装ハンズオン系

「記事で読んだ技術を実際に試してみたい」読者向け。E-E-A-T が最も重要。
note が「概念・設計」を書いたなら、このブログは「動かすまでの具体的な手順」を担う。

**主語のルール（絶対厳守）**
- 「副業」を主語にしない。「この技術を試してみた」「実装してみてわかったこと」を主軸にする。
- 例: 「副業に使うために試した」→ NG / 「仕組みを理解するために実際に動かしてみた」→ OK
- 「お金になるか」「稼げるか」という問いかけは使わない。「どう動くか・どこで詰まるか・何が面白いか」を書く。

## note (uta_lab_) 連動ルール（このファイルの核心）

このブログ記事は、uta_lab_ の note 記事の「実装編・深掘り版」として機能する。

### 連動パターン
- note「サブエージェント実例（Claude）」→ アフィ「Claude APIでサブエージェントを動かすまでの手順と詰まりポイント」
- note「MCPサーバー設計」→ アフィ「MCPサーバーをローカルで動かすまでの手順、環境構築から動作確認まで」
- note「RAGの設計思想」→ アフィ「LangChainでRAGをゼロから実装した、詰まった3点と解決策」
- note「プロンプトエンジニアリング実例」→ アフィ「Claudeのシステムプロンプトを改善した手順、before/afterと変化」

### 記事冒頭の連動案内（任意）
「note (uta_lab_) でこの技術の設計思想・概要を書きました。この記事はその実装編です。」
という自然な文章を冒頭に入れてよい。ただし強制ではなく、流れに合う場合のみ。

### テーマ選定の優先順位
1. note 直近記事で取り上げた技術を「実際に動かす」ハンズオン
2. 最新のAI/開発ツールのセットアップ・試用体験
3. 技術概念を「動くコード・操作」で理解する記事

## 構成
- 冒頭: 「〜が気になったので実際に試してみました」「note で書いた〜を実装してみました」と動機から入る
- H2構成: 「試した背景・目的」→「環境・前提条件」→「実際の手順（ステップ番号付き）」→「詰まったポイントと解決策」→「試して感じたこと・総評・CTA」
- 具体的な操作手順・コマンド・エラーメッセージの描写でリアリティを出す
- 「結論: 〇〇な人には試す価値あり、△△な人は別の方法を検討してもよい」と明確に締める
- 体験していないこと・実行していないコードは絶対に書かない

## タイトル多様性ルール（厳守）

### 禁止テーマパターン（過去記事と被らせない）
過去記事一覧が別途提示される。その一覧を必ず確認し、以下を守ること:
- 「AI画像生成で副業」の切り口は作らない（禁止フレーズ）
- 「AIブログアフィリエイト」の切り口は作らない（禁止フレーズ）
- 「副業」を主語・前面に出したタイトルは作らない（技術実装が主語であること）
- 過去記事に同じ技術を対象にしたハンズオン記事がある場合は別技術・別切り口にする

### 禁止語尾パターン（連続3本以内に同じものを使わない）
- 「〜正直な感想」「〜正直レビュー」「〜正直な結果」
- 「〜わかったこと」「〜わかった」「〜気づいたこと」
- 「〜全手順」「〜完全ガイド」
- 「〜本音」「〜リアルな感想」
- 「〜注意点」（handson で頻出のため注意）

### 検証対象の多様化ルール
handson 記事の対象が偏らないようにすること:
- AIモデル・API系: Claude API / OpenAI API / Gemini API 等（同じサービスを連続させない）
- フレームワーク・ライブラリ系: LangChain / LlamaIndex / FastAPI / Next.js 等
- 開発環境・ツール系: Cursor / GitHub Copilot / Dify / n8n 等
- インフラ・デプロイ系: Vercel / Railway / Supabase / Cloudflare Workers 等

### 記事切り口9種のローテーション（必ず現在未使用の切り口を選ぶ）
handson タイプでも切り口を変えること:
1. How-to型: 「〇〇のセットアップ手順、初心者がつまずいた3点を添えて」
2. Why型: 「なぜ自分は〇〇を選んだのか、技術的な理由を整理した」
3. 比較型: 「〇〇を使ってみて、以前の〇〇と実装体験が何が変わったか」
4. 解説型: 「〇〇の仕組みがよくわかっていなかったので実装して理解した」
5. 誤解解消型: 「〇〇は難しいというイメージで試したら、実は〇〇だった」
6. 提案ツール型: 「〇〇の目的に使えるライブラリを3つ試して絞り込んだ」
7. リスト型: 「〇〇を初めて動かすときにやっておくべき5つの設定」
8. 物語型: 「〇〇を0から動かすまでにかかった時間と詰まった経緯の記録」
9. 疑問型: 「〇〇って非エンジニアでも実装できるのか、試した結果」

過去記事一覧の傾向を見て、最もカバーされていない切り口を選ぶこと。

### タイトル生成時の確認手順
1. 候補タイトルを3案考える（対象技術・語尾・視点がすべて異なるもの）
2. 過去記事一覧と照合し、ツール名・語尾・テーマが被っていないか確認
3. 「副業」が主語になっていないか確認
4. 最も新鮮な切り口の1案を選ぶ

### タイトル形式
- 30文字以内、SEOキーワード（技術名・ツール名）を含む
- 「実際に動かした」「試した」「実装した」など手を動かした感を前面に
- NG: 「副業のためにClaude APIを試してみた」（副業が主語）
- NG: 「AI画像生成ツールを副業に使った手順」（禁止フレーズ）
- OK: 「Claude APIをゼロから動かした、環境構築から最初のレスポンスまで」
- OK: 「LangChainでRAGを実装した、詰まった3点と解決策」
- OK: 「MCPサーバーをローカルで動かすまでの手順をまとめた」
- OK: 「Difyで自作エージェントを作った、1時間で動くまでの記録」

## アフィリエイトCTA（技術習得・効率化文脈で使う）
- スクール系 → 「この技術を体系的に学ぶなら」という文脈でWinスクール無料カウンセリングへ誘導
- WordPress/サーバー系 → 「手を動かす環境を整えるなら」という文脈でエックスサーバーへ誘導
- AIツール系 → 「この技術を使えるサービスを手軽に試すなら」という文脈でConoHa AI Canvas等へ誘導
- CTAは「広告」「PR」と明示 (絶対厳守)

- Markdownのテーブル記法 (| xxx |) は絶対禁止
- 捏造・架空の実績・数値主張は絶対禁止
- 実際に実行していないコマンド・コードを正確であるかのように書くことは禁止
- 文字数は別途指定される (それに従う)
